Extra 05 — MCP de 24/11: skills, tasks, elicitation e arquivos

Skills over MCP · Tasks · Elicitation · File Uploads · tool search Produto atual · fora da prova
Na prova, vale o guia. Esta aula extra cobre novidades que a Anthropic apresentou em 24/11/2026 (live Claude Code: Advanced e anúncios do mesmo dia), conferidas na documentação em 24/11/2026. Nada daqui cai na CCAR-F como está; as questões são de fixação e não entram no simulado nem no progresso das 14 aulas.
🎯 Objetivo. Entender as quatro novidades do MCP anunciadas em 24/11/2026 (o servidor ensina com skills, recebe tarefa longa com Tasks, pede confirmação com Elicitation e troca arquivos com File Uploads), o status de cada uma, e onde elas mudam o desenho de um servidor: em especial, a Elicitation como trava técnica para ação de decisão.

1. O servidor MCP quase como outro agente

A Aula 05 tratou o MCP como a forma de dar ao Claude acesso a sistemas externos: tools são ações, resources são conteúdo. O anúncio de 24/11 deixa o Claude trabalhar com um servidor MCP quase como trabalharia com outro agente: o servidor ensina, recebe tarefa longa, pede confirmação ao usuário e troca arquivos.

Tudo faz parte da especificação aberta do MCP e das suas extensões: um servidor que implementa funciona em qualquer cliente compatível, não só no Claude.

2. Skills over MCP: o playbook viaja com o servidor

Até aqui, skill (o procedimento que se repete) e MCP (o acesso a sistema externo) eram coisas separadas: a skill ficava no repositório ou em ~/.claude/skills/, e o servidor só trazia tools. Com Skills over MCP, o servidor leva o próprio playbook.

  • A skill carrega sob demanda, então o contexto continua enxuto.
  • Atualiza junto com o servidor: quem usa não instala nada máquina por máquina.
  • No Claude Code, o nome é <servidor>:<skill> (por exemplo, docs:pdf); aparece ao digitar / ou em /skills. Exige a v2.1.331 ou mais recente.
  • Não funciona em claude -p, no Agent SDK nem em sessões na nuvem, e depende de modelos específicos e de conexão direta com a Anthropic.
  • No auto mode, o classificador decide se a skill carrega. Dá para bloquear com uma regra deny Skill(mcp__docs__*), ou exigir confirmação com ask.
  • Aviso da documentação: skills podem mandar o Claude rodar código, e o servidor pode mudá-las a qualquer momento. Adicione só servidores em que você confia.

Exemplo de uso: um servidor de assinatura de documentos pode levar as regras da casa (sempre usar o modelo aprovado, validar o telefone antes de enviar) junto com as tools, em vez de cada usuário copiar essas regras para o próprio CLAUDE.md.

3. Tasks: operação longa sem travar a sessão

Uma MCP task é um trabalho longo, como gerar um relatório ou rodar um build, que o próprio servidor executa usando a extensão de tasks.

  • A chamada volta assim que o servidor aceita o trabalho, e o Claude segue trabalhando. Quando a task termina, o transcript mostra uma linha dizendo que acabou e o Claude recebe o resultado; peça a ele.
  • Independentemente de tasks, na conversa principal de uma sessão interativa, uma chamada MCP que passa de dois minutos rodando vai para segundo plano (em modo não interativo, só com CLAUDE_AUTO_BACKGROUND_TASKS=1).
  • A task de um servidor remoto continua depois que você sai; a de um servidor local (stdio) para junto com o Claude Code.
  • Exige a v2.1.304 ou mais recente no terminal (a v2.1.331 no VS Code e no app desktop); um claude -p "..." de execução única não recebe MCP tasks. A especificação é uma extensão do MCP, e o suporte varia de cliente para cliente.

Exemplo do anúncio: uma pesquisa mais profunda de contas e contatos, que antes levava vários prompts, roda como task enquanto o Claude segue com o resto.

4. Elicitation: a trava técnica para ação de decisão

Com Elicitation, o servidor pausa no meio de uma chamada e pede algo ao usuário. O Claude Code mostra um diálogo e devolve a resposta ao servidor, sem configuração nenhuma do seu lado.

  • Form mode: um formulário com os campos que o servidor definiu (por exemplo, o nome do projeto e uma data).
  • URL mode: o Claude Code pergunta se abre um link no navegador, para um fluxo que termina fora do terminal, como um login.
  • Recusar também é uma resposta: o servidor decide se continua.
  • Numa sessão interativa, um hook Elicitation pode responder automaticamente, sem diálogo.
  • Já a elicitation de uma MCP task em claude -p ou no Agent SDK não chega a ninguém: o Claude Code pede ao servidor que cancele a task, sem rodar os hooks Elicitation nem o callback onElicitation do SDK. O cancelamento é cooperativo: quem para o trabalho é o servidor.

Por que isso importa: até agora, "confirme antes de cobrar" ou "confirme antes de apagar" dependia só da instrução no prompt, ou seja, de orientação. Com Elicitation, o próprio servidor se recusa a seguir sem a resposta da pessoa. Exemplos do anúncio: confirmar o custo antes de criar um projeto pago, confirmar antes de rodar SQL destrutivo, digitar o nome do repositório antes de um agente apagá-lo.

É a mesma lição da Aula 03 e da Aula 07: o que precisa ser garantido não fica só no prompt. A diferença é onde mora a trava: no hook e na regra deny ela está no seu Claude Code; na Elicitation, está no servidor, e vale para qualquer cliente que fale com ele.

5. File Uploads e tool search

File Uploads (ainda chegando em 24/11) deixa o Claude mandar arquivos, e não só texto, ao servidor: PDF, planilha e imagem vão direto, sem passar pela janela de contexto. Um contrato vai inteiro para o servidor de assinatura sem ocupar o contexto da sessão.

Tool search já era da Aula 05: as definições das tools carregam só quando precisam. O anúncio trouxe o número: em configurações com vários servidores, pode cortar mais de 85% do contexto gasto com definições de tools (dado da Anthropic, sem as condições do teste). Ele vem ligado por padrão nos modelos suportados.

Também no anúncio: com o Enterprise Managed Auth, o admin autoriza um servidor suportado uma vez e os usuários conectam automaticamente. Sem ele, cada pessoa entra no servidor remoto com a própria conta, pelo /mcp ou por claude mcp login.

⚠️ Pegadinha

Skill sobre MCP não é "skill grátis e segura". Ela carrega sob demanda e atualiza com o servidor, mas pode mandar o Claude rodar código, e o servidor pode mudá-la a qualquer hora. Confie no servidor antes, e use regra deny ou ask se precisar.

Elicitation não é instrução no prompt. "Peça confirmação antes de cobrar" escrito no prompt é orientação; o servidor que pausa e exige a resposta da pessoa é trava. No Agent SDK ou em claude -p, a elicitation de uma task faz o Claude Code pedir ao servidor que cancele a task (não a aprova), e nem o hook Elicitation roda.

7. Questões de fixação

Pontuação: 0/0
Questão 1 · múltipla escolha
Um servidor MCP de assinatura de documentos quer que todo cliente siga as regras da casa (sempre usar o modelo aprovado) sem que cada usuário edite o próprio CLAUDE.md. Qual novidade resolve?
Gabarito: B. Com Skills over MCP o servidor publica o procedimento junto com as tools; ele carrega sob demanda e atualiza com o servidor, sem instalar nada em cada máquina. Elicitation pede uma resposta pontual ao usuário, não ensina procedimento. Tasks são trabalho longo. File Uploads mandam arquivos ao servidor, não instruções ao Claude.Fonte: anúncio de 24/11; docs: mcp
Questão 2 · múltipla escolha
Um servidor vai rodar uma operação de cobrança. Hoje, a confirmação depende de uma instrução no prompt. Qual novidade transforma isso numa trava técnica?
Gabarito: C. Com Elicitation o próprio servidor pausa e exige a resposta do usuário por formulário ou link; sem ela, não segue. Uma skill dizendo "confirme" ainda é orientação ao Claude, como o prompt. Tool search trata de carregar definições, não de confirmar. Tasks rodam em segundo plano, não pedem aprovação.Fonte: anúncio de 24/11; docs: mcp
Questão 3 · múltipla resposta (marque DUAS)
Quais DUAS afirmações sobre Skills over MCP estão corretas no Claude Code em 24/11/2026?
Gabarito: A e C. O nome é <servidor>:<skill>, e regras de permissão sobre Skill(mcp__docs__*) bloqueiam ou pedem confirmação. A Anthropic escaneia skills só de alguns conectores; servidores adicionados com claude mcp add, por exemplo, não passam por esse escaneamento. E não está liberado para todo Enterprise: no Claude Code, com login de Team ou Enterprise, as skills de MCP ficam desligadas até a organização ligar.Fonte: docs: mcp
Questão 4 · múltipla escolha
Um servidor MCP precisa provisionar uma máquina, o que leva dez minutos. O que as MCP Tasks mudam na sessão?
Gabarito: B. Com Tasks, a chamada volta assim que o servidor aceita o job, e, quando ela termina, o Claude recebe o resultado. Sem tasks, numa sessão interativa, uma chamada que passa de dois minutos vai para segundo plano; não é cancelada. E quem executa a task é o servidor, não uma sessão na nuvem.Fonte: docs: mcp
Questão 5 · múltipla escolha
Um agente feito com o Agent SDK roda sem ninguém olhando e dispara uma MCP task. No meio, o servidor usa Elicitation para confirmar uma ação destrutiva. O que acontece?
Gabarito: D. No Agent SDK e em claude -p, a elicitation de uma MCP task faz o Claude Code pedir ao servidor que cancele a task, sem rodar os hooks Elicitation nem o callback onElicitation. Ninguém aprova no lugar da pessoa e a ação não segue sozinha. O hook que responde automaticamente vale numa sessão interativa, não nesse caso.Fonte: docs: mcp
Questão 6 · múltipla escolha
Por que File Uploads importa para mandar um contrato em PDF a um servidor de assinatura?
Gabarito: A. File Uploads manda PDF, planilha ou imagem ao servidor sem passar pelo contexto. Não há conversão nem resumo, o servidor não ganha acesso livre à sua máquina, e nada vai para o CLAUDE.md. Em 24/11, File Uploads ainda estava chegando.Fonte: anúncio de 24/11
Questão 7 · múltipla escolha
Sua sessão tem muitos servidores MCP ligados. Segundo o anúncio, o que o tool search faz e quanto economiza?
Gabarito: B. Tool search carrega as definições das tools só quando preciso; o anúncio diz que pode cortar mais de 85% menos contexto em configurações com vários servidores. Ele não desliga servidores, não junta tools nem resume definições com outro modelo. O número é da Anthropic, sem as condições do teste publicadas.Fonte: anúncio de 24/11
Questão 8 · múltipla escolha
Você escreve um servidor MCP com Tasks e Elicitation. Segundo o anúncio, onde ele funciona?
Gabarito: C. O anúncio diz que as novidades fazem parte da especificação aberta do MCP e das suas extensões, e que um servidor que as suporta funciona em qualquer cliente compatível, mesmo que o suporte varie de cliente para cliente. O Claude Code suporta Elicitation, e o Managed Auth é outra coisa: autorização centralizada pelo admin.Fonte: anúncio de 24/11; modelcontextprotocol.io
