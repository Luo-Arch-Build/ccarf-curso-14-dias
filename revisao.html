Priority 01

Lesson 12 · Context Management & Escalation

Domain 5 · Context Management & Reliability · 15 cards

Full lesson
  1. QWho preserves conversation state between Messages API requests?
    AThe application preserves state and resends the messages, tool calls, and tool results needed for coherence; the API keeps no state between requests.
  2. QHow do you preserve exact facts while summarizing a long conversation?
    AExtract and verify exact IDs, amounts, dates, decisions, and customer commitments before summarizing; persist them in a case-facts block outside the summary and inject that block into later requests.
  3. QHow do history, context, structured state, and a summary differ?
    AHistory is the stored exchange; context is what this request sends to the model; structured state is exact data persisted outside history and reinjected when needed; a summary is compressed history that loses detail.
  4. QWhat is the correct mitigation for lost-in-the-middle failures?
    APut a key-findings summary at the start of the aggregated input and organize detailed results under explicit section headers; metadata alone does not fix the positional effect.
  5. QWhat should an upstream subagent return when downstream context is limited?
    AReturn a schema-validated SubagentResult with a concise summary, key facts, citations, errors, and status instead of verbose reasoning; an example object alone is not a validation contract.
  6. QHow do L1, L2, and L3 verification depths differ?
    AL1 validates structure and metadata on every result; L2 opens each cited source and checks that its excerpt supports the claim entering synthesis; L3 examines methodology, contradictions, and independent confirmation for high-impact or disputed claims.
  7. QHow does the coordinator verify upstream work without repeating the investigation?
    AEach citation supplies source, locator, exact excerpt, and content_hash; the coordinator checks those points and quarantines failed claims instead of searching again, while the hash only detects changed content rather than proving truth or authenticity.
  8. QWhich four techniques manage a growing context window?
    ACombine summarization, a structured state object, a sliding window, and selective retention according to what must survive; they are complementary rather than competing techniques.
  9. QWhere should verbose tool results be reduced, and what should remain in context?
    ATrim irrelevant fields in the tool or integration layer before they enter history; then selectively extract-persist-reinject exact facts, summarize decisions and rationale, and remove content that has already served its purpose.
  10. QDoes a sliding window of N turns impose a token or cost limit?
    ANo: turns vary in size and early facts fall out of the window, so use a token budget and cut policy together with immediate extraction of durable facts.
  11. QWhat are the three legitimate escalation triggers?
    AEscalate for an explicit human request, a policy exception or gap, or inability to make meaningful progress; complexity, frustration, sentiment, and raw self-confidence are not escalation triggers.
  12. QHow should over-escalation and under-escalation be corrected first?
    AWrite observable criteria for both escalation and non-escalation, add few-shot examples on both sides of the boundary, and measure precision and recall separately before considering a dedicated classifier.
  13. QWhat should the agent do when a lookup returns multiple possible customers?
    AAsk for an additional identifier such as email, tax ID, or order number; never guess by recency or location because selecting the wrong customer can disclose private data.
  14. QHow should exploration findings survive compaction and phase boundaries?
    APersist exact findings in scratchpads or manifests, inject phase summaries into the next phase's subagents, run directed compaction with preservation instructions, and verify the result item by item before acting.
  15. QWhat makes crash recovery safe in a multi-agent pipeline?
    APersist versioned artifacts and an atomic RunManifest, reconcile task states, artifacts, hashes, and external effects before resuming, treat crashed in_progress work as unfinished, and use idempotency keys or deduplication for side effects.

Priority 02

Lesson 06 · CLAUDE.md Hierarchy, Imports, and Rules

Domain 3 · Claude Code Configuration & Workflows · 9 cards

Full lesson
  1. QWhich three CLAUDE.md levels does the exam test?
    AUser level is ~/.claude/CLAUDE.md for personal cross-project preferences; project level is the root or .claude/CLAUDE.md shared through git; directory level is a subdirectory CLAUDE.md loaded while working in that tree.
  2. QDo CLAUDE.md files override one another?
    ANo: applicable files load together and their instructions add up in the session context.
  3. QWhy does a new teammate miss rules stored in ~/.claude/CLAUDE.md?
    AThat file is personal and outside version control; move shared conventions to the versioned project CLAUDE.md at the repository root or .claude/CLAUDE.md.
  4. QHow do /memory and /context support different diagnoses?
    AUse /memory to locate, open, or create memory files; use /context and its Memory files section to inspect what loaded at session launch.
  5. QHow do you diagnose rules that load only on demand?
    AReproduce access to a matching file and inspect the terminal's Loaded line or an InstructionsLoaded hook; one launch-time /context call cannot list files that may load later.
  6. QDoes splitting a large CLAUDE.md with @import reduce context by itself?
    ANo: @path/to/file modularizes maintenance, but imported content still loads; path-scoped rules are what reduce irrelevant context.
  7. QHow does .claude/rules/ help modularize project guidance?
    AIt stores focused, versioned topic files such as testing.md and api-conventions.md instead of one monolithic CLAUDE.md, with optional YAML paths globs for conditional loading.
  8. QWhen does a rule with paths enter the context?
    AIt loads when Claude works with a matching file through Read, Write, Edit, or a recognized single-file Bash read such as cat or head; loading is not limited to edits.
  9. QWhy use **/*.test.tsx instead of directory CLAUDE.md files for scattered tests?
    AThe glob follows the file type across directories, while a directory CLAUDE.md is bound to its own tree; deterministic loading still leaves model adherence probabilistic, so guarantees require code.

Lesson 07 · Slash Commands, Skills, Permissions, and Plan Mode

Domain 3 · Claude Code Configuration & Workflows · 14 cards

Full lesson
  1. QWhere should a team-shared slash command live?
    AStore its Markdown file in the repository's .claude/commands/ directory so git distributes it; ~/.claude/commands/ is for personal shortcuts.
  2. QHow does a skill differ from CLAUDE.md?
    AA skill is an on-demand procedure whose description stays available and whose SKILL.md body loads when used; CLAUDE.md supplies persistent project guidance and is not an occasional workflow.
  3. QWhat do context: fork, allowed-tools, and argument-hint do in SKILL.md?
    Acontext: fork isolates execution in a subagent; on the exam allowed-tools restricts available tools; argument-hint tells the user which parameters to supply.
  4. QWhich skill rules follow the exam guide rather than current product behavior?
    AOn the exam, commands and skills are distinct and allowed-tools restricts tools; in the current product they are unified, allowed-tools only pre-approves, and disallowed-tools removes access.
  5. QHow should you personalize a project skill without changing the team's workflow?
    ACreate a differently named variant under ~/.claude/skills/; editing or committing personal changes to the project skill would affect everyone.
  6. QHow do you map common needs to the right configuration mechanism?
    AUse project CLAUDE.md for universal standards, a paths rule for file-type conventions, a skill for occasional parameterized workflows, a slash command for a named shared prompt, and a personal command or skill for private shortcuts.
  7. QWhen should you use a deny rule versus a PreToolUse hook?
    AUse deny for an unconditional target that matches a tool, command, or path pattern; use PreToolUse when blocking or rewriting depends on conditions such as environment, branch, or amount.
  8. QHow are permission rules evaluated?
    AEvaluation is deny, then ask, then allow, and deny always wins; a personal allow cannot reopen a project deny.
  9. QWhat is the settings-file precedence from strongest to weakest?
    AManaged organization policy, command-line arguments, .claude/settings.local.json, project .claude/settings.json, then ~/.claude/settings.json; permission lists combine across files.
  10. QHow do PreToolUse hook decisions and exit codes work?
    ApermissionDecision can allow, deny, or ask, updatedInput can rewrite the call, and exit 2 blocks without JSON; exit 1 does not block by default, and a hook allow cannot override a deny or skip an ask.
  11. QWhich hooks fit a formatter and a validator?
    ARun a formatter in PostToolUse after a successful edit; run a blocking validator in PreToolUse before the action executes.
  12. QWhen is direct execution preferable to plan mode?
    AUse direct execution for a simple, understood, well-scoped change; per-edit permission prompts already provide supervision and do not turn the task into plan mode.
  13. QWhen do plan mode and a multi-phase workflow apply?
    AUse plan mode when design uncertainty requires exploration and approval before edits; use a multi-phase workflow when separate phases produce artifacts and require explicit handoffs and independent human or programmatic gates.
  14. QWhat does plan approval authorize, and how is the same plan implemented headlessly?
    AIt authorizes implementation, not production or deployment; a later headless run must explicitly resume the session or receive the approved plan artifact and its context, while external release gates remain separate.

Lesson 04 · Tool Descriptions, Distribution, and tool_choice

Domain 2 · Tool Design & MCP Integration · 11 cards

Full lesson
  1. QWhat is the first fix when an agent confuses two similar tools?
    AExpand and differentiate their descriptions; minimal or overlapping descriptions are the primary cause of unreliable selection, so start there instead of adding routing infrastructure.
  2. QWhat belongs in a high-quality tool description?
    AState domain-specific purpose, accepted input formats, example user queries, edge cases, and boundaries that say when to use this tool instead of a similar one.
  3. QHow should severely overlapping tools be redesigned?
    ARename and specialize them, or split a generic tool into single-purpose tools with clear input and output contracts; names and descriptions both guide selection.
  4. QWhat if good tool descriptions still fail around a literal keyword?
    AInspect the system prompt and rewrite keyword-sensitive routing as intent-based guidance, such as using lookup_order for order-status questions rather than anything containing the word order.
  5. QWhy should each agent receive only role-relevant tools?
    AA smaller scoped tool set reduces semantic overlap, decision complexity, and cross-role misuse; follow least privilege rather than treating any specific tool count as a quota.
  6. QHow do you stop an agent from using a generic tool outside its role?
    AReplace it with a constrained alternative whose handler validates and rejects disallowed targets, such as load_document instead of unrestricted fetch_url; descriptions and schemas alone do not enforce that semantic policy.
  7. QCan a specialist receive a tool normally associated with another role?
    AYes, if it is narrowly scoped to a frequent need: give synthesis a limited verify_fact for simple checks while complex investigation still goes through the coordinator to the research agent.
  8. QHow do tool_choice auto, any, and forced selection differ?
    Aauto permits text or a tool; any requires some tool while allowing a choice; forced selection requires the named tool, such as extract_metadata.
  9. QWhen is tool_choice the right guarantee?
    AUse it when the model must emit a tool_use in this turn; an imperative prompt remains probabilistic, while tool_choice controls the requested emission.
  10. QDoes forced tool selection guarantee successful execution and workflow order?
    ANo: tool_choice controls emission, while application code executes the handler and a prerequisite gate validates success and business data before enabling the next step.
  11. QWhat is the correct client-tool loop across turns?
    AThe model emits tool_use with id, name, and input; the application executes and validates the handler, preserves the assistant block, returns tool_result with the matching tool_use_id, and keeps later steps blocked after failure or invalid output.

Lesson 08 · Iterative Refinement and Claude Code in CI/CD

Domain 3 · Claude Code Configuration & Workflows · 14 cards

Full lesson
  1. QHow do you make an ambiguous transformation converge consistently?
    AProvide 2–3 concrete input/output examples that demonstrate capitalization, null handling, formats, and field names instead of adding more prose.
  2. QWhat does test-driven iteration look like?
    AWrite tests for expected behavior, edge cases, and performance first; implement, run them, and feed back exact failures with input, expected output, and actual output until the suite passes.
  3. QWhen should Claude interview you before coding?
    AUse the interview pattern in an unfamiliar domain so Claude surfaces requirements, constraints, and failure modes you did not know to specify; a longer prompt cannot describe unknown considerations.
  4. QHow should interacting and independent issues be iterated?
    APut interacting fixes in one detailed message so their shared behavior stays coherent; handle independent fixes sequentially because they do not invalidate one another.
  5. QWhich flag prevents Claude Code from hanging for input in CI?
    AUse -p or --print to process the prompt, write the result to stdout, and exit; shell redirections and timeouts do not provide the same behavior.
  6. QHow do --output-format json and --json-schema work together?
    AThe first produces parseable JSON and the second constrains valid structured output; consume the validated structured_output field only after checking that the run succeeded and the field exists with the expected type.
  7. QWhat does missing structured_output mean?
    AIt means the run did not produce valid structured output, not that there were zero findings; fail the job explicitly instead of substituting an empty findings array.
  8. QWhat does dontAsk do in a non-interactive job?
    AIt denies calls that would require approval while actions that need no prompt continue; allow rules, allowedTools, and approving hooks can still permit specific calls, so it is not an absolute allowlist.
  9. QWhen are bypassPermissions and acceptEdits appropriate?
    AUse bypassPermissions only in an isolated container or VM, with deny rules and denying hooks still effective; use acceptEdits for a code-generation job that may edit in the working directory, not for a read-only reviewer.
  10. QHow do --max-turns and --max-budget-usd contain runaway work?
    AThey cap agentic turns and client-estimated spend in -p mode; the budget is not a hard billing cap, and legitimate limit failures call for adjustment or task splitting rather than removing the safeguard.
  11. QHow do --tools, --disallowedTools, and --allowedTools differ?
    A--tools restricts built-ins, --disallowedTools removes built-in or MCP tools, and --allowedTools only pre-approves without restricting availability; removing Edit and Write is insufficient while Bash remains available.
  12. QWhat is the shape of a read-only PR-review job?
    AUse -p with dontAsk, --tools Read,Grep,Glob, --disallowedTools mcp__*, turn and budget limits, JSON output and schema, and a prompt that reports rather than fixes findings.
  13. QHow does --bare improve CI reproducibility?
    AIt skips automatic discovery of host memory, hooks, skills, plugins, and MCP configuration; supply reviewed context explicitly, for example with --append-system-prompt-file CLAUDE.md, while -p separately controls non-interactive execution.
  14. QHow do Claude Code Action and managed Code Review differ, and how do repeat reviews stay clean?
    AUse the Action with claude_args when you control workflow flags and limits; managed Code Review comments without commits and reads REVIEW.md from the base branch, and every rerun receives prior findings so it reports only new or unresolved issues.

Lesson 13 · Error Propagation, Human Review, and Provenance

Domain 5 · Context Management & Reliability · 12 cards

Full lesson
  1. QWhat error context should a subagent send to the coordinator?
    ASend structured failure type, attempted query or parameters, partial results, and alternative approaches, with an explicit status such as partial_failure; a vague error string is insufficient for recovery.
  2. QWhich failures should a subagent resolve locally, and what happens next?
    AHandle transient failures locally with backoff or a reformulated query; propagate only unresolved failures with their full context so the coordinator can retry, switch source, re-delegate, or proceed with an annotated gap.
  3. QHow should synthesis handle partial research coverage?
    AIdentify well-supported findings and explicitly name areas whose sources failed or remained incomplete; never hide coverage gaps behind fluent prose.
  4. QWhy is high aggregate accuracy insufficient before reducing human review?
    AAggregate accuracy can hide weak document types and fields; measure performance by document segment and by field before changing the review policy.
  5. QHow does field-level confidence become a calibrated routing signal?
    ACalibrate thresholds on a labeled validation set for each field-by-segment slice; a raw model score is only an input signal, not a probability of correctness.
  6. QWhich conditions independently trigger human review?
    ALow calibrated confidence, an unvalidated segment, ambiguity or contradiction, and high impact are OR conditions: any one is enough, and a high score does not cancel another trigger.
  7. QWhen can a field be auto-approved, and what audit still applies?
    AAuto-approve only when no trigger is active and that field-by-segment slice is validated; keep auto-approved fields in a separate stratified random audit sample to measure real errors and support recalibration.
  8. QHow does targeted triage differ from audit sampling?
    ATargeted triage reviews known risks identified by triggers; audit sampling examines auto-approved items to discover missed patterns, so sampling complements rather than replaces triage.
  9. QHow do the extraction reviewer, domain specialist, and authorization owner differ?
    AThe extraction reviewer checks the flagged value and necessary excerpt, the domain specialist resolves interpretive ambiguity, and the authorization owner approves high-impact or irreversible action; reviewing data is not authorizing its use.
  10. QWhat belongs in a claim-source mapping?
    APair each claim with its source URL or document, relevant evidence excerpt, locator where useful, and publication or collection date, and preserve those mappings through synthesis.
  11. QHow should credible sources with conflicting statistics be handled?
    APreserve both values with their sources and methodological contexts, pass the conflict to the coordinator for reconciliation, and keep the analysis alive rather than choosing, averaging, or discarding evidence.
  12. QHow should dates and certainty appear in the final report?
    AKeep publication_date, using null when unknown, distinguish temporal change from contradiction, separate well-established from contested findings, and render financial data as tables, events as prose, and technical findings as structured lists.

Lesson 02 · Coordinator and Subagent Orchestration

Domain 1 · Agentic Architecture & Orchestration · 11 cards

Full lesson
  1. QWhy does hub-and-spoke route subagent communication through the coordinator?
    ACentral routing provides observability, consistent error handling, and controlled information flow; direct subagent-to-subagent channels hide decisions and failures from the coordinator.
  2. QWhat are the coordinator's four core responsibilities?
    ADecompose the full query, delegate distinct scopes to the right specialists, aggregate structured results, and dynamically select only the subagents the query requires.
  3. QAll subagents succeeded, but the report covers only one niche. Where is the defect?
    AThe coordinator's decomposition was too narrow: the subagents executed their assigned scopes correctly, so fix topic-dimension enumeration and coverage checks in the coordinator.
  4. QHow does an iterative refinement loop close coverage gaps?
    AThe coordinator evaluates synthesis for gaps, re-delegates targeted queries with the missing context, reruns synthesis with the new findings, and repeats until coverage is sufficient.
  5. QWhat must the coordinator have to spawn subagents on the exam?
    AIts allowedTools must include Task; the current product calls this tool Agent and treats allowedTools as pre-approval, but the exam follows the guide's Task requirement.
  6. QWhat does an AgentDefinition configure, and how must it be wired?
    Adescription guides coordinator selection, prompt defines the specialist's role and output, and tools restricts capabilities; register the definition in the coordinator's agents option because merely declaring it does not make it available.
  7. QHow do you diagnose common subagent-spawning failures?
    ANo delegation at all points to missing Task permission; one unavailable agent points to missing wiring; wrong-agent selection points to descriptions; the right agent exceeding its role points to tools and system prompt.
  8. QWhat must a self-contained Task prompt include?
    AInclude objective, scope and boundaries, complete findings with evidence and source metadata, permitted sources and tools, quality and completion criteria, output schema, and instructions for reporting errors and gaps; subagents inherit neither history nor memory between calls.
  9. QWhat must the coordinator verify before accepting a subagent result?
    ACheck scope coverage, claim-source attribution, required structure, and declared errors or gaps; fluent prose and a successful tool status do not prove correctness, so re-delegate any explicit gap before aggregation.
  10. QHow do you run independent and dependent subtasks correctly?
    AEmit multiple Task calls in the same coordinator response for independent work; put dependent work in a later turn with all required upstream results explicitly in its prompt.
  11. QHow much autonomy should an open-research subagent receive?
    ASpecify objectives, quality criteria, scope, tools, output, and completion contract while leaving search queries and source order adaptable; mandatory procedures still require workflow enforcement and coordinator verification.

Lesson 11 · Message Batches and Multi-Pass Review

Domain 4 · Prompt Engineering & Structured Output · 10 cards

Full lesson
  1. QWhich three numbers define the Message Batches API value proposition?
    AIt is asynchronous, costs 50% less than synchronous requests, and can take up to 24 hours with no latency SLA.
  2. QWhich workloads belong in batch, and does polling change that decision?
    AUse batch for latency-tolerant, non-blocking work consumed hours later, not real-time replies or merge-blocking checks; polling is normal tracking but neither shortens processing nor creates an SLA.
  3. QHow do you correlate batch requests with out-of-order results?
    AAssign a unique custom_id to each request and match results and failures by the returned custom_id rather than by list position.
  4. QWhat is the exam's client-tool limitation for a batch request?
    AA single batch item cannot run the application-driven multi-turn loop of tool_use followed by tool_result; orchestrate that loop outside the item, without generalizing this into a ban on every kind of tool.
  5. QHow often should batches be submitted under a 30-hour delivery SLA?
    AUse submission interval plus 24 hours plus margin within the SLA; the guide's 4-hour interval gives 28 hours total and a 2-hour margin, while 6 hours is the theoretical zero-margin ceiling.
  6. QHow should batch failures and prompt refinement be handled?
    AFix causes and resubmit only failed custom_id items, and refine prompts on a small synchronous sample before a large run; sample testing improves first-pass success but does not change the 50% discount.
  7. QWhy is an independent review instance stronger than self-review?
    AIt receives the diff or code and review criteria without the generator's reasoning history, avoiding the assumptions and self-confirmation bias that extended thinking in the same session cannot remove.
  8. QHow do per-file and cross-file passes address attention dilution?
    AReview each file in a focused pass for local issues, then run a separate integration pass for cross-file contracts and data flow; a larger context window or repeated identical passes does not provide that focus.
  9. QWhy specialize review passes by concern?
    ASecurity, business logic, and API design examples compete for recall in one prompt, so use independent focused passes with their own few-shot examples and merge their findings.
  10. QHow can confidence route findings after a verification pass?
    ACalibrate confidence thresholds against labeled confirmed and dismissed findings; send low-confidence findings to triage or another pass rather than deleting them, and never treat raw confidence as truth.

Lesson 05 · Structured Errors, MCP, and Built-In Tools

Domain 2 · Tool Design & MCP Integration · 12 cards

Full lesson
  1. QHow does an MCP tool communicate failure to the agent?
    AReturn a tool result with isError: true and readable error content so the agent can reason about recovery; failure is data, not necessarily a crashed agentic loop.
  2. QHow do transient, validation, business, and permission errors differ?
    ATransient errors warrant backoff or retry; validation requires corrected input; business violations require explanation or escalation without retry; permission failures require credentials, scope, or human intervention.
  3. QWhat structured error metadata prevents blind retries?
    AInclude errorCategory, isRetryable, and a human-readable description, with a customer-friendly explanation for business violations; Operation failed gives the agent no recovery decision.
  4. QHow does an access failure differ from a valid empty result?
    AA valid empty result is a successful query with no matches; an access failure means the query did not complete and must carry isError plus category and retryability instead of pretending that no data exists.
  5. QWhere are shared and personal MCP servers configured?
    AUse a versioned project-root .mcp.json for servers the whole team needs and ~/.claude.json for personal servers that should not travel through git.
  6. QHow can .mcp.json share configuration without committing secrets?
    AReference environment variables such as ${GITHUB_TOKEN} instead of hardcoding tokens; the config is shared while each developer supplies the secret locally.
  7. QWhat should you check before rewriting an unused MCP tool's description?
    ARun /mcp or claude mcp list to verify connection status, approval, missing environment variables, and exposed tool count; only a connected server with discovered tools can have a selection problem.
  8. QWhen should content be exposed as an MCP resource?
    AExpose catalogs such as issue summaries, documentation hierarchies, and database schemas as resources when the agent wastes exploratory calls discovering what exists; tools perform actions while resources provide content visibility.
  9. QWhen is a custom MCP server justified?
    APrefer existing community servers for standard integrations such as GitHub, Jira, Slack, or Postgres; build custom servers for team-specific workflows that existing servers do not cover.
  10. QHow do Grep, Glob, Read, Write, and Edit differ?
    AGrep searches file contents, Glob finds paths by pattern, Read inspects a file or range, Write creates or replaces complete content, and Edit makes a surgical replacement using a unique anchor.
  11. QWhat is the reliable fallback when Edit's anchor is not unique?
    ARead the whole file, modify the intended content, and Write it back; do not repeat the same ambiguous Edit or bypass it with sed.
  12. QHow do you explore a large codebase without overstating completeness?
    ADefine the question and stopping criterion, narrow candidates with Glob and Grep, read minimal evidence, follow re-exports and local aliases to actual invocations, log file:line evidence and exclusions, and report dynamic or unresolved calls as boundaries rather than absence.

Lesson 01 · The Agent SDK and the Agentic Loop

Domain 1 · Agentic Architecture & Orchestration · 8 cards

Full lesson
  1. QHow do you consume query() and recognize the final Agent SDK result?
    AIterate query() with async for, handle AssistantMessage blocks while work progresses, and read ResultMessage.subtype for the final outcome; query() is an asynchronous message stream, not one synchronous HTTP response.
  2. QWho controls the loop in Agent SDK, Messages API, and Claude Code CLI?
    AThe Agent SDK manages the loop and built-in tools; a Messages API application executes client tools and returns tool_result itself; Claude Code manages the CLI loop while scripts control flags, context, permissions, and output handling.
  3. QWhich stop_reason values control the basic agentic loop?
    AOn tool_use, execute every requested tool, append all matching results to history, and call again; on end_turn, stop and deliver the final response; never infer completion from assistant text.
  4. QHow should other stop_reason values be treated?
    ATreat max_tokens and model_context_window_exceeded as incomplete output, follow the configured rule for stop_sequence, resend the current response to continue after pause_turn, and handle refusal rather than blindly retrying.
  5. QWhat is the contract for multiple tool_use blocks in one response?
    AExecute all of them, in parallel when independent, and return every tool_result together in one user message with matching tool_use_id values; failed tools also need results because an unmatched tool_use invalidates the next request.
  6. QWhy can separate user messages for parallel tool results reduce later parallelism?
    AThey make the history demonstrate one call per turn; return results together instead, and use disable_parallel_tool_use: true only when serialization is intentional.
  7. QHow do model-driven tool selection and access control coexist?
    AThe model chooses which available tool to call and when to stop, while the runtime defines each role's exposed tool perimeter; this differs from a fixed decision tree and does not grant unrestricted access.
  8. QHow do you configure a read-only Agent SDK reviewer?
    AExpose only the required read tools, remove write and shell capabilities with disallowed_tools, and use dontAsk; allowed_tools pre-approves rather than forming a complete allowlist, and the SDK does not load .env automatically.

Lesson 03 · Enforcement, Hooks, and Session Management

Domain 1 · Agentic Architecture & Orchestration · 8 cards

Full lesson
  1. QWhen is a prerequisite gate required instead of stronger prompting?
    AUse a gate whenever identity verification, a value limit, or tool order is mandatory: code blocks downstream execution until the prerequisite is valid, whereas prompt guidance always has a nonzero failure rate.
  2. QWhat makes a human handoff actionable without transcript access?
    ASend fixed fields with the verified customer ID, established root cause, amount involved, and recommended action; the human should act without rereading or repeating the diagnosis.
  3. QHow should one message containing several customer concerns be handled?
    ADecompose it into distinct items, investigate them in parallel with the same verified context, and return one unified resolution that closes every item rather than answering only the first.
  4. QWhen should a PreToolUse hook intercept a call?
    AUse it before execution to prevent a policy violation and optionally redirect the model with permissionDecision deny and a reason; PostToolUse is too late to undo an action.
  5. QWhen is PostToolUse the right normalization mechanism?
    AUse it to transform heterogeneous tool results, such as Unix timestamps and numeric statuses, into canonical values before the model processes them; mechanical normalization belongs in code rather than prompt instructions.
  6. QWhen do prompt chaining and dynamic decomposition fit?
    AUse prompt chaining for predictable sequential stages known in advance; use dynamic decomposition for open investigations whose next tasks depend on intermediate discoveries.
  7. QWhen should you resume a session versus start fresh?
    AResume a named session when its context remains valid and identify specific changed files for targeted reanalysis; start fresh with a structured summary when tool results are stale or the codebase changed substantially.
  8. QWhen is fork_session the right operation?
    AUse fork_session to explore divergent approaches from one shared analysis baseline; each branch inherits that baseline and then evolves independently.

Lesson 09 · Explicit Criteria and Few-Shot Prompting

Domain 4 · Prompt Engineering & Structured Output · 7 cards

Full lesson
  1. QWhat reduces false positives better than be conservative or high-confidence filtering?
    ADefine testable categorical criteria for exactly what to report and what to skip, such as flagging a comment only when its claimed behavior contradicts actual code behavior.
  2. QWhat should you do while repairing a review category with many false positives?
    ATemporarily disable that category, rewrite it with explicit criteria and few-shot examples, then re-enable it; noisy categories also erode trust in accurate categories.
  3. QHow do you make severity labels consistent across reviews?
    ADefine each severity level with an explicit behavioral criterion and a concrete code example, rather than relying on labels such as major or minor alone.
  4. QWhich project knowledge belongs in persistent review context?
    ADocument project conventions, intentionally accepted patterns, and exclusion criteria so every review can distinguish real defects from team decisions and out-of-scope code.
  5. QWhere should persistent and one-off review criteria live?
    AKeep persistent criteria in versioned CLAUDE.md, path-scoped rules, or managed-review REVIEW.md; keep a one-off exception in that run's prompt so it does not affect future reviews.
  6. QWhat makes few-shot examples effective?

  1. QWhy is tool use with a JSON schema the exam's most reliable structured-output method?
    AThe extraction tool's input_schema makes the model return structured tool input instead of prose, eliminating JSON syntax and formatting failures by construction; strict: true enforces exact schema conformance in the current product.
  2. QHow do prompt formatting, prefill, and tool use differ on the exam?
    APrompt formatting offers no guarantee, prefill only forces the response to begin inside JSON, and tool use with a strict schema imposes structure; choose according to how much deviation the consumer can tolerate.
  3. QHow should output that grows with input size be prevented from truncating?
    ASplit the work into smaller scoped calls with the same schema and merge, deduplicate, and recalculate results in code; raising max_tokens only fits a predictable fixed-size output that barely exceeds a low configured limit.
  4. QWhat remains to validate after strict schema validation succeeds?
    AValidate semantics in application code: totals may disagree and values may occupy the wrong fields while remaining schema-valid; schema guarantees shape, not meaning.
  5. QHow should a schema represent missing, ambiguous, or novel source values?
    AUse optional or nullable fields for absent information, unclear for ambiguity, and other plus a detail string for new categories so the schema does not pressure the model to fabricate.
  6. QShould normalization happen in a hook or in the prompt?
    ANormalize values returned by tools in PostToolUse code; normalize values the model reads from documents with prompt rules and examples alongside the schema, because the error originates in interpretation rather than transport.
  7. QWhat makes retry-with-error-feedback effective, and when is it useless?
    AResend the original document, the failed extraction, and specific validation errors so the model can correct inconsistent fields; if the source lacks the information, supply it or accept null instead of repeatedly pressuring for fabrication.
  8. QHow can a schema support self-correction for inconsistent totals?
    AExtract calculated_total from line items alongside the document's stated_total and set conflict_detected when they disagree, exposing source inconsistency instead of silently choosing one value.
  9. QWhy record detected_pattern on each review finding?
    AGroup dismissed findings by the construct that triggered them to identify weak rules and refine the tool from evidence; this records what fired the finding, not how confident the model felt.
