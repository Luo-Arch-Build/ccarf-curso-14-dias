Auto mode: o classificador tira as confirmações de rotina

Na aula: settings.permissions com allow/ask/deny; deny bloqueia sempre; hook PreToolUse para proibir sob condição.
  • Desde a v2.1.283, o auto mode é o modo inicial das sessões interativas no terminal e no VS Code; claude -p e o Agent SDK continuam começando no modo default.
  • No auto mode, um classificador revisa cada ação para você não precisar aprovar uma a uma.
  • As regras deny bloqueiam em todos os modos, inclusive no bypassPermissions: o classificador decide o que é rotina, a regra deny é o limite rígido.
  • Na demo do /batch da live, um arquivo protegido por regra foi pulado pelos subagents. A documentação não afirma isso para o /batch especificamente; o que ela diz é que subagents herdam o modo da conversa principal.
  • Consequência prática: o que não pode acontecer nunca (deploy de produção, apagar dados, disparo em massa) vai em regra deny, não só em texto no CLAUDE.md.

Plan mode ainda vale?

Na aula: execução direta para mudança pequena e clara; plan mode para mudança grande, ambígua ou com várias abordagens.
  • No Q&A, um engenheiro respondeu que o plan mode basta para alinhar a implementação.
  • Outro prefere pedir que o Claude o entreviste antes de planejar, porque o plano sai longo demais.
  • As duas práticas convivem: a entrevista reduz a ambiguidade antes do plano; o plan mode continua sendo o lugar de revisar a abordagem antes de editar.
Fonte: Q&A da live de 24/11

Skill ou MCP?

Na aula: skill (SKILL.md) é um procedimento carregado sob demanda; MCP é configurado em .mcp.json.
  • Regra do Q&A: skill é um procedimento que se repete; MCP é a forma de acessar contexto externo.
  • Desde 24/11, um servidor MCP também pode levar skills (Skills over MCP), em beta: o procedimento viaja junto com o acesso.
Fonte: Q&A da live de 24/11; claude.com/resources/articles/skills-over-mcp-tasks-and-more
